# 本轮修复与验收报告

日期：2026-10-30（Asia/Shanghai）。模型仍为 `gpt-4o-mini`；设备、规则、工单均为模拟数据。原模型配置、六轮上限、六条规则、原 12 条用例及预期均未改变。历史成功、失败和 blocked 报告继续保留。

本轮结果：**原 12 条真实评测 12/12 通过，新增 4 条不同表述用例 4/4 通过；最终业务镜像的容器真实探针和 3 个真实 HTTP 业务场景均通过。** 这是一轮小规模验证，不能解释为任意自然语言输入都正确，也不是生产安全认证。

## 实际改动及其依据

### 用户事实与补充后的依赖失效

基线 C04、C05、C07 的完整 trace 显示：补充后 `resolved_asset_id` 被无差别清空，模型却继续请求规则；泛化拒绝反馈没有帮助它完成前置步骤，最后耗尽六轮。

新增 [`facts.py`](../src/maintenance_agent/facts.py) 从 `HumanMessage` 中收集设备线索、故障描述和停机情况，并记录原用户消息序号和引用。助手消息、工具参数和工具结果不被用来确认用户的停机事实；计划、建议、假设、未确认和冲突状态不能自动变成“已停机”。模型自行传入与用户事实不一致的停机值会被拒绝。

[`graph.py`](../src/maintenance_agent/graph.py) 增加 `reconcile` 节点，在初次受理和补充后更新事实并按依赖使结果失效：

- 同一设备的故障或停机情况变化，使规则和草案失效；已核实设备不再被无差别丢弃。
- 身份/位置线索变化、此前未唯一核实或旧 checkpoint 没有事实缓存时，由图完成必要的台账前置查询。新增身份描述即使最终仍指向同一设备，也会接受一致性核实。
- 自动查询以 `automatic_tool` 独立记录来源、参数和结果，不调用模型，不增加模型请求数或六轮计数。原 12 条本轮共记录 3 步自动查询，不把这些步骤藏进调用数下降中。
- 模型每次看到当前用户事实及来源、台账核实结果、缺失字段、规则有效性和合法工具，不需要从笼统报错中反复猜测下一步。

### 只追问缺失字段与明确工具协议

基线 C02、C11 在已有明确摘要和停机情况时仍追问，且首轮将查询和追问混在一个批次。现在 [`llm.py`](../src/maintenance_agent/llm.py) 使用 `parallel_tool_calls=False`，并按当前状态绑定合法工具：设备核实、缺字段追问、规则查询、草案提交分步推进。重新绑定工具列表不会执行额外模型请求。

服务端仍验证协议。异常混合批次中的每个 call 都会留下拒绝记录和对应 `ToolMessage`，不会静默丢弃。信息完整时的额外追问被拒绝并标记 `redundant_question`；仍缺信息时，服务端只生成缺失/冲突字段对应的实际问句。日志同时保留模型请求的原问法与实际展示问句；评测优先读取工具结果里的实际问句。

C11 本轮继续完成合法报修草案，优先级/班组由原规则与台账决定；P0、越权班组和跳过审批的指令没有进入草案执行路径。提示词没有加入完整评测题或标准答案。

### 通用设备引用解析

基线 C09 的查询 `EQ-010 包装机` 含有效 ID，但旧台账查询将整个字符串匹配为未知设备。现在 [`domain.py`](../src/maintenance_agent/domain.py) 提取完整显式 ID，再核对附加名称、别名和位置：

- ID 精确选择，不截断、不纠错、不通过名称替换未知 ID。
- 多个 ID、ID 与名称/位置冲突或身份描述无法核实时，返回歧义/冲突并要求澄清。
- 不含 ID 的名称、别名、位置使用台账一致性约束；明确区分 `found`、`not_found`、`ambiguous`、`conflict`。
- 图还会核对完整用户身份线索，避免模型缩短查询词后隐藏原文的冲突信息。

这些规则针对设备引用的一般结构，不按用例编号或整句文本特殊处理。设备存在但没有适用分派规则仍独立返回 `no_matching_rule`。

### 人工确认和幂等保持

`approval` / `execute` 与业务存储的批准约束保持：人工确认通过 `interrupt` 恢复同一任务，批准绑定服务端保存的当前 `draft_id`，执行节点读取保存草案，不再生成草案；只有批准后的执行路径可以创建工单。唯一请求键继续保证重复确认和提交后崩溃恢复只保存同一张工单。取消不建单，跨补充/恢复的六轮累计不重置。

## 容器网络与数据保留

原失败是容器直连出口问题：DNS 成功、IPv4 TCP 超时、IPv6 网络不可达。核验发现现有代理由 Windows 的 verge-mihomo 在回环地址监听；WSL 没有对应本机监听，但可以连接它。容器自己的 `127.0.0.1` 不能代替 Windows/WSL 主机回环。

采用项目级配置 [`compose.runtime-proxy.yaml`](../compose.runtime-proxy.yaml) 与 [`runtime_proxy.py`](../scripts/runtime_proxy.py)：中继只监听本项目 Docker 私有 bridge 网关，只接收该项目子网的连接，转发到当前环境中经过校验的无认证回环 HTTP 代理；原主机代理值不写进项目。API 使用动态网关别名，API/UI 的 NO_PROXY 排除内部服务和回环地址。没有关闭 TLS 校验、修改全局网络/防火墙或在镜像中写入密钥。

最新容器探针让中继连接数实际增加，验证模型 HTTP 客户端确实使用了配置；内部 API 访问不增加中继数，验证内部通信未误走代理。配置和复现方式见 [网络修复报告](network_fix.md)。

真实 HTTP 验证新增了三条带“容器真实测试/模拟数据”标签的任务，其中正常确认和补充确认各建一张测试工单，取消场景不建单：

- 正常确认：任务 `1634812f706b4811a1c5fc0628c613e3`，工单 `WO-D791E4E3F144`。
- 补充后确认：任务 `c4d35e759b0345c58aa1165968032d57`，工单 `WO-1020F2BA3BEA`。
- 取消：任务 `e99a79b52c004941a446bff384067a4b`，没有工单。

`preexisting_rows_unchanged=true`：原有两条任务在业务表和 checkpoint 表中的全部原有行保持不变。这里不是“整库未变化”——新增测试任务、事件和两张测试单有意保留。验证没有删除原数据卷或清理历史数据。

## 最新 3 分钟演示建议

演示前保持当前 WSL 代理中继会话，确认 API/UI 已用 runtime override 启动。打开 [Streamlit](http://localhost:8501) 与 [API 文档](http://localhost:8000/docs)，核对容器真实探针报告已通过。重新创建容器时使用 `compose.yaml` 与 `compose.runtime-proxy.yaml` 的完整组合，网关从最新拓扑报告读取；不要用只有 base Compose 的 force-recreate 覆盖运行时代理设置。

1. **0:00–0:20：说明边界。** 单 Agent；全部业务数据为模拟；模型负责提取/分类和工具选择，服务端负责事实来源、台账、规则、批准与落库。
2. **0:20–1:00：正常报修并确认。** 输入 `【容器真实测试：正常；模拟数据】EQ-001 机械轴承异响，已经停机。`，展示规则依据、草案 ID、批准前无订单，再确认展示工单号。
3. **1:00–1:45：补充信息并确认。** 输入 `【容器真实测试：补充；模拟数据】EQ-004 机械轴承振动明显增大。`，看到只问是否停机；补充 `已经停机。`，展示设备核实保留、规则重算和六轮累计，再确认。
4. **1:45–2:15：取消。** 输入 `【容器真实测试：取消；模拟数据】EQ-005 电机电气保护跳闸，已经停机。`，草案形成后取消，展示没有工单。
5. **2:15–3:00：查看证据和限制。** 区分模型调用与自动步骤，展示 114 条离线/mock 回归、原 12 与新 4 两份真实报告、容器真实探针和真实 HTTP 三场景报告。明确旧失败仍在、总耗时反而增加，以及事实解析的适用边界。

如需额外展示重启恢复，可将一条新任务停在待确认，复制任务 ID，重启 API 后恢复同一草案再批准；恢复和重复确认的回归证据已在离线/mock 测试中验证。这是额外现场步骤，不冒充本轮三项容器 HTTP 场景已经包含了重启测试。

## 当前局限

本轮验收用例没有剩余失败，但 12+4 是有限样本、单次运行，不代表稳定的泛化成功率。字段提取采用保守的通用规则和用户原文摘录，仍可能在复杂否定、跨句指代、非标准设备名称、计划与实际状态交织等语句中漏提或误判；指令截断也可能丢掉合法信息。故障类别仍由模型选择，摘要未达到企业词典规范，必要时需要人工澄清。

合法工具约束、台账校验和人工批准能限定流程边界，不能替代真实企业安全审查或维修决策。本项目没有真实设备控制、企业系统权限、生产级鉴权、审计留存制度或高并发多副本能力。代理中继是当前 Windows/WSL 环境适配，依赖原代理可用；网络或代理发生变化应重新 inspect 和验证，不是普适的部署方案。没有实际验证云部署。
